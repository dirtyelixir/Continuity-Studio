# 按內容推薦導演風格

DirectorSKILL 已接入為 Astra 的導演方法資料庫。推薦讀取作品原文、既有劇本／分鏡及使用者視覺方向，比較 20 套方法，再提出三個有排序的選擇。每個選擇包括逐字劇情引述、適合原因、構圖運鏡、走位、剪接節奏、光色、套入故事的單一關鍵幀例子，以及實際取捨。這是創作判斷，不是客觀分數或四套 skill 的盲測。

製作手冊的「適合這個故事的導演風格」可啟動推薦。選擇「採用這個方向並建立分鏡方案」後，系統把選定導演的完整方法模組交給原有分鏡能力；同一方案只用一套 lens。方法須落到鏡頭和關鍵幀內容，不能只加導演名字。新方案仍先審閱才採用。也可取消已選方向、直接使用原有方向，或稍後重新推薦。

優先順序是使用者原文、對白、既有 canon、明確媒材／畫幅／時長要求，再到導演方法。定格動畫不會因選擇實拍導演而變成真人。上游長鏡頭或省略敘事的建議要適配 Studio 的 4–15 秒鏡頭及來源完整性，不能刪掉必要動作。圖片、影片及 H3 沿用採用後的 Production；單是選擇方向不會修改既有 production、資產或提示詞。

## 版本與資料流

- 新 capability `director_style` 預設 Astra gpt-6-astra，可獨立改用 HTTP／人工。未變更其他能力的服務商，沒有降級備援。
- 固定上游 [DirectorSKILL](https://github.com/wuwangzhang1216/DirectorSKILL) commit `c65ae0d14457053efb1e354c7e7f7e120d97fad1`（SKILL 2.1.0），MIT LICENSE 與逐檔 SHA-256 存於 `studio/bundled/director-skill/`。這個內建適配器使用 20 個風格模組，並不宣稱載入上游全部製作 pipeline、模型 adapter 或執行 scripts。
- 推薦使用由模組原文提取的適用場景、反例、完整 YAML 參數目錄；選定後才載入單一完整模組的指示及模板。
- Job 保存當時的內容、版本、目錄 hash、三個建議及精確引述。程式驗證 ID 合法、三位不同、引述來自實際內容。這些結構檢查不等於證明藝術判斷正確。
- 選擇存於 SQLite settings `director_style:PROJECT_ID`，附來源工作與具體拍法。只能選本作品目前內容的成功建議；跨作品、舊內容、非候選導演會被拒絕。
- 選擇方向不增 production revision；建立的 narrative/storyboard job 凍結選擇及 hash。方向改變後，舊方向的未採用方案不可覆蓋目前決定。正在處理另一方向的工作也不會被誤報為新方向工作。
- 採用新方案後，推薦會因內容版本不同而需重新產生；已選方向保留。介面分開標示下一份方案的方向與已採用方案使用的方向；章節方案只標示最近採用章節，不宣稱重寫全作品。
- 匯出 `director-style.json` 分開記錄 selected（目前意向）、applied（在採用交易中記錄、且仍吻合目前 production 的方向）及目前有效推薦。舊工作證據仍保存在 jobs。

驗證：`tests/test_director_styles.py` 覆蓋資料來源、候選合法性、人工結果、跨作品／舊版本阻擋、單模組 prompt、既有原文及 production 保護、方向改變的採用阻擋、並行工作識別及匯出意向／已套用區分。實際 Astra／瀏覽器驗收記錄見 STATE.md。
