# Model context adaptation

New text jobs freeze a `context-v1` policy in their provider configuration: context capacity, reserved output, safety margin, tokenizer and provenance. Provider changes and later capacity edits do not alter existing jobs. Studio budgets are conservative application defaults, not claims about a model's advertised maximum. Settings exposes per-provider capacity/output controls and a local Qwen choice through the existing `127.0.0.1:8080/v1` VRAM Manager gateway; adding that choice does not change routing.

Local Qwen uses passive `/props` discovery for the active per-slot capacity, then `/apply-template` and `/tokenize` through that gateway. It never calls the private llama server or changes GPU services. Runtime shrinkage and failed tokenization stop before generation instead of silently switching to an estimate. Other text providers use the complete UTF-8 byte count as a deliberately conservative token upper bound, including the output JSON schema. This may refuse a request which the provider's native tokenizer could fit; it must not be presented as an exact count. HTTP requests explicitly set the reserved `max_tokens`. Legacy frozen jobs retain their previous transport/checkpoint identity.

## Chapter context

The chapter pipeline compares each scene, shot, edit or coverage stage's full request against its frozen budget. If it fits, it remains intact. If it does not fit:

1. Generate a read-only source index in bounded batches directly from original source units. Each checkpoint contains source-to-scene spans, direct-source navigation summaries and exact quoted anchors. Validation requires every original unit in order exactly once, valid scenes and recall IDs, and verbatim anchor quotations. A recall naming a known scene expands to all original units mapped to that scene, including transitive dependencies; an unmapped or unknown reference fails closed. No summary is repeatedly summarized.
2. Build a context pack containing unchanged canon, the complete frozen screenplay and scene overview, full current-scene source units, transitive recall sources, all grounded chapter anchors (including future reveals), the source navigation, director feedback, series outline and previous-chapter context. Shot tasks retain all shot briefs, completed-shot boundaries and the previous full shot. Coverage tasks retain a chapter-wide shot action/dialogue catalog plus full details for source-linked scenes.
3. Measure that exact assembled request plus schema. Required context is never sliced or removed just to make it fit. If it still exceeds capacity, stop with a specific explanation and preserve source/index/stage checkpoints. No provider fallback or automatic paid upgrade occurs.

Chapter writing can deduplicate repeated source copies while retaining the complete original source, approved production, canon and feedback. A foundation that still cannot fit must be split into chapters or assigned a sufficient explicit budget; this implementation does not pretend a summary can replace an unread original chapter. Other non-chapter text jobs receive budget preflight without chapter-specific source retrieval; directing review now has its own staged audit described below. Image attachments are outside this text-token accounting and must not be described as measured by it.

Shot-detail batches shrink from three to one for smaller output budgets. Coverage batches shrink below the existing maximum of 80. These sizes are output-planning heuristics, independent of actual input token accounting. A single output unit can still exceed the selected output budget; its complete prior checkpoints remain available and partial output is never adopted.

Every provider attempt retains its actual request, context selection receipt, count method and budget receipt. Stage identity still binds the full frozen source and original task. Retries reuse valid completed source-index and production checkpoints. The job detail panel exposes full/scoped/deduplicated mode, token count and selected/remaining source-unit counts. Original source, adopted canon and candidate/adoption gates remain authoritative; structural provenance validation is not a guarantee of semantic directing quality.

Acceptance evidence: `data/acceptance/context-adaptation-20260913/`.

The HTTP adapter unwraps a complete Markdown JSON code fence only after the entire inner document parses; the original provider output and normalization receipt are preserved. It never salvages truncated JSON. This avoids unnecessary regeneration when Qwen returns a valid structured document inside a formatting envelope.

Protocol references consulted: [llama.cpp server endpoints](https://github.com/ggml-org/llama.cpp/blob/master/tools/server/README.md) and [DeepSeek chat-completion output limits](https://api-docs.deepseek.com/api/create-chat-completion/). Live Qwen capacity is read from the installed server, not inferred from a public model card.

Live acceptance: the original 天水圍 last-shot request counted 151,592 native Qwen tokens. A real Qwen run indexed all 663 original units in 21 saved batches, resumed through preserved checkpoints and generated the requested last shot from an 89,554-token scoped request, passing structural stage validation. The final implementation also includes the unchanged frozen screenplay; its exact measured pack is 91,126 tokens with 8,192 reserved output. Complete original source, canon and previous-shot boundaries remain available and unchanged. This is evidence of context transport/retrieval and structured generation, not proof of equal artistic quality across models. The generated isolated candidate was not adopted.

## Output exhaustion accounting

DeepSeek requests ask for usage in the final stream event. Transport keeps only numeric prompt/completion/reasoning token counts and reasoning-character counters, never reasoning text. The requested max_tokens remains the frozen output budget; no automatic increase, retry, provider switch or reasoning downgrade occurs. A length finish is incomplete even when an answer looks parseable. Historical missing usage is unknown, not zero. Job details expose safe root-attempt budget receipts and show exhaustion separately from input preflight. A passing input check does not guarantee the model completes within its output allocation.

## Staged directing review

New automatic directing reviews freeze `directing-stages-v1` when the complete request exceeds the frozen input budget or the beat count exceeds the output planning batch size. Small fitting reviews keep the original path. Historical failed jobs retain their original input; a new retry gets the new planner.

Before any provider call, Studio measures every exact request plus its transport schema. Local batches shrink down to one scene/beat, retaining every complete linked Shot/keyframe, every competing beat linked to those Shots, canon, full story/screenplay and selected edit uses. No source strings are sliced. Global review retains original story/screenplay, direct-source event/learning navigation for every beat, beat-to-Shot links and the entire actual edit order. Separate overlapping boundary checks retain full screenplay, original timed action/dialogue and states, selected canon and each adjacent edit use, including reused sources. The global phase owns narrative/reveal ordering; local phases own frozen-moment/frame readability; boundary phases own cut-point continuity. Explicit phase authority prevents omitted, separately reviewed fields being treated as user omissions. Cross checks are batched by exact union size and output allocation.

All local beats and every global/boundary check must complete. Exact-ID/evidence checks reject omissions, duplicates and fabricated quotations. Aggregation retains nonpass checks as issues and uses the most restrictive verdict; the existing whole-plan review validator and human adoption gates still apply. A source/provider/prompt/schema-bound completion receipt is required to finish/recover a staged job. A single necessary original unit that cannot fit stops explicitly; output sizing is a heuristic, not a guarantee that reasoning and structured output will finish.

Each successful batch has a hashed checkpoint. Explicit resume uses the frozen provider and budget, validates source freshness, and processes only unfinished batches. Valid complete raw outputs can be recovered after interruption; length-finished output cannot. Each resumed transport attempt has a distinct directory, and transport failures do not automatically repeat calls. One structural/evidence correction may run, without changing a substantive verdict to obtain acceptance. Cancellation blocks further stages and adoption. The normal proposal and job views show saved batch counts and resume controls; historical errors are not rewritten.
