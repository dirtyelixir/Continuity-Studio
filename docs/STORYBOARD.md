# Visual storyboard workflow

Continuity Studio now plans and displays an ordered visual board between the adopted director/edit plan and H3 production. The board is available at **鏡頭與分鏡**, above source Shot details, and is the normal progress recommendation after canonical references are ready.

1. **由導演安排圖板** dispatches `storyboard_frames` through the configured creative provider. Mandatory Studio methods 1.5.0 include the pinned visual-skills dramaturgy, montage and the visual-board contract. One scene per request; existing source direction, dialogue, cut order and canon remain authoritative.
2. Inspect the proposed exact-time anchors and adopt the arrangement. Each edit use, including a repeated source, gets an opening anchor at its selected edit-in. Extra anchors need a concrete visual-state/evidence purpose. Existing same-source/time frames are reused. New interior frames carry `moment: key`, `source_time`, description and explicit frozen state. Sources support up to eight frozen frames. No image is generated by adopting a plan.
3. **補齊缺少圖片** previews required targets, reused approved images, pending candidates, active/unresolved work and missing canonical references. Submission uses the chosen actual image provider and existing prompt-preparation/render/review pipeline. Durable intent receipts prevent replay after interrupted/uncertain submission. No automatic provider downgrade or fake generation.
4. Inspect each image with its cut reason, intended moment and neighboring view context. Approving a panel also explicitly approves its selected pending image through the existing asset checks. A separate panel receipt binds current source, anchor and image bytes. Marking a panel `revise` retains the original image and review history. Replacing the approved image, changing bytes/source, or adopting a different board requires renewed review.
5. The board feeds H3 grouping and render checks. Native I2VA/FL2VA groups may use a reviewed interior key exactly at a trimmed outer boundary. Source start/end frames retain their original time meaning. Intermediate keys never become extra automatic inputs in legacy H3 or Ref2VA's “both endpoints” option. Explicit Ref2VA groups can select role-labelled storyboard frames alongside identity references, within their existing nine-image limit.
6. Export includes `storyboard/index.html`, manifest and only current panel-approved images. Missing/unreviewed panels stay visibly incomplete. It is an ordered board, not a generated contact-sheet image or proof of filmed cuts.

An adopted board is binding for downstream work in its scene. Existing projects without an adopted board retain their original direct H3 paths; the ordinary production guide now points users to prepare the board first. Supplemental interior stills do not by themselves rewrite/revoke the source director decision or invalidate unchanged endpoint image hashes. They have their own exact-frame image and board review. Changing an existing endpoint or source direction still follows normal invalidation.

State is stored in `storyboard:<project_id>`; adoption persists the production and board in one transaction with optimistic revisions. Historical board/review receipts remain in settings. Batch receipts use `storyboard-batch:*`. The existing canonical SQLite store and image originals remain authoritative.

Verification: `tests/test_storyboard_board.py` covers 18 isolated cases (schema/state/time validity, legacy hashes and H3 refs, complete ordered adoption, reuse restrictions, source/asset freshness, image-bound approval, trimmed native group conditioning, durable batch behavior and complete export). Existing related source/directing/delivery/render/provider/workflow regressions and Node UI checks pass. A real configured DeepSeek run successfully returned three ordered panels on an isolated copy of The Smallest Fix. Browser acceptance adopted that result only in the copy, imported an existing real frame, and recorded its visibly premature lit-lantern state as `revise`. No new image or video was generated by this acceptance; final rendered-montage quality remains to be inspected.


## Generation-needed image planning (2026-09-14)

New `generation-needed-images-v1` requests supersede the legacy extra-anchor policy above. Each panel first declares `image_plan` (I2VA/FL2VA, rationale, exact source evidence, unresolved constraints), then exactly the images that existing full-source execution will use. I2VA uses source 0; FL2VA uses source 0 and source duration. `planning_notes` retains ordinary acting/review beats without generating images or requiring picture approval. Repeated edit uses share source mode and assets; full-source endpoints can lie outside the edit trim and are labelled accordingly. Adoption saves board and video mode atomically. Historical boards and original approval receipts retain their prior contract.

An unresolved hard intermediate constraint stops batching and H3 handoff. Internal Generation Segments are not Editorial Shots and are not automatically implemented by adding graph entries; seamless joining and exact source-time mapping remain necessary work.
